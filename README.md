# СберИндекс 2026: прогноз расходов МО и ранняя детекция структурных сдвигов

Работа в номинации «Прогнозирование» онлайн-конкурса СберИндекса. Методологический отчёт - `docs/report.md`.

## Идея в трёх строках

1. Лог расходов МО раскладывается на общую траекторию категории и локальную часть МО:
   `log y_it = n_ct + z_it`. Большую часть ошибки прогноза даёт общая часть, поэтому её прогнозируем
   по длинному национальному ряду СберИндекса «Потребительские расходы» (с 2018 г.):
   у панели всего 24 месяца, у национального ряда - почти 8 лет сезонности.
2. Локальная часть - модель пространства состояний `z = mu + r` (случайное блуждание уровня +
   AR(1)), параметры оцениваются ММП по всей панели категории фильтром Калмана.
3. Структурный сдвиг - ступенька в уровне `mu`; детектор - LR-тест ступеньки в той же модели.
   Новости (каталог событий по МО) повышают априорную вероятность сдвига.

## Установка

Нужен Python 3.12 (prophet, ruptures и torch пока не собираются под 3.14).

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv --extra-index-url https://download.pytorch.org/whl/cpu --index-strategy unsafe-best-match -r requirements.txt
```

Данные не хранятся в репозитории. Скачайте `hackathonlicence.zip` со страницы конкурса и распакуйте
в `data/`, чтобы получилось `data/hackathonlicence/consumption.parquet` и т. д. Другой путь можно задать
в `config.local.yaml` (не в git):

```yaml
data:
  dir: D:/path/to/hackathonlicence
output_dir: D:/path/to/out
```

## Запуск

```bash
python -m sbi.forecast
python -m sbi.report
python -m sbi.detect_eval
python -m sbi.detect_real
```

`sbi.forecast` без аргументов строит все модели; одну или несколько - `--models panel_ssm prophet`.
Время на 16-ядерном CPU: Prophet около 40 мин, Chronos-2 около 15 мин на вариант, остальное - минуты.
Веса Chronos-2 (`amazon/chronos-2`) и TimesFM 2.5 (`google/timesfm-2.5-200m-pytorch`, ~800 МБ) скачиваются с Hugging Face при первом запуске; TimesFM - около 12 мин на вариант.

Результаты складываются в `out/`: прогнозы `forecasts/*.npz`, метрики `metrics.csv`,
тесты Диболда-Мариано `dm_vs_baseline.csv`, детекция `detection_*.csv`.

## Конфигурация

Все пути и гиперпараметры - в `config.yaml`: схема валидации (точки начала прогноза, горизонты),
параметры каждой модели, детекторов и синтетического эксперимента.

## Структура

| Файл | Что делает |
|---|---|
| `sbi/data.py` | панель (МО x категория) x месяц |
| `sbi/national.py` | прогноз общей компоненты категории по национальному ряду СберИндекса |
| `sbi/models/panel_ssm.py` | центральная модель: фильтр Калмана по панели, ММП |
| `sbi/models/baselines.py` | наивная, сезонная наивная, Prophet (базовая модель конкурса) |
| `sbi/models/lgbm.py` | LightGBM на панели с признаками соседей по графу дорог |
| `sbi/models/panel_seasonal.py` | разложение с собственной сезонностью МО |
| `sbi/models/chronos_fm.py` | Chronos-2 без дообучения по сырым рядам |
| `sbi/models/fm_local.py` | TimesFM 2.5 и Chronos-2 на локальной компоненте (лог минус общая траектория), TimesFM по сырым рядам |
| `sbi/models/ensemble.py` | итоговый ансамбль: среднее в логах пяти моделей на разложении |
| `sbi/news.py` | каталог событий -> множители вероятности сдвига (без заглядывания вперёд) |
| `sbi/detect.py` | детекторы: CUSUM, PELT, BOCPD, LR-тест в модели пространства состояний |
| `sbi/detect_eval.py` | сравнение детекторов на вставленных ступеньках |
| `sbi/evaluate.py`, `sbi/report.py` | MAE, R², WAPE, тест Диболда-Мариано |

## Данные третьих сторон

- `ref/mo_names.csv` - справочник «territory_id - название МО» из метаданных датасета
  «Потребительские безналичные расходы на уровне муниципальных образований»;
- `ref/consumer_spending_national.csv` - датасет «Потребительские расходы» (РФ, млрд руб. в месяц).

Источник обоих - СберИндекс, https://sberindex.ru, лицензия CC BY-SA 4.0 (данные скачаны 07.10.2026).
`ref/events.csv` - каталог событий, составлен вручную по открытым источникам (указаны в файле).
